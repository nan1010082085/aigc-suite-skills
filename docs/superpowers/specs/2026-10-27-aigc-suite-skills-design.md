# aigc-suite-skills 设计稿（漫剧创作五 skill 套件）

> 2026-10-27 ｜ 与用户逐轮对齐后的定案。此文档经用户批准后才动工建 skill。

## 一、意图与为什么

前作上线后播放与完播双低。复盘诊断：IP 选材偏小众（根因，但 IP 选择只归用户，不做 skill）；产线各环节能力不专——流程大一统、剧本提炼弱、分镜表达不专业（运镜/转场/镜头语言缺失）、人物建模不稳、出片无质检。

**解法**：把产线拆成五个独立 skill（本套件），每个环节的能力规格拉满：分镜创作=虚拟导演+即梦提示词工程师；人物素材=调研驱动的资产工厂；出片检查=三道硬闸。**三条留存主轴贯穿全部 skill，既是产出标准也是自检项**：

1. **场景转场连贯**——转场必交代时间+地点+空间延续，同场景多镜共用同一套场景资产
2. **剧情分镜**——钩子结构、节奏密度、镜头细切到可拼接
3. **人物建模质量**——三视图锚点制资产+出图前置调研+风格库

## 二、目标 / 非目标 / 反目标

**目标**
- 五个 skill：小说改编、想法创作、分镜创作、人物与场景素材、出片检查
- 剧本层两核心（用户 2026-10-27 定）：**灵活叙事**（节奏紧凑、镜头精炼、快速成片）、**剧本理解**（深度理解、读懂每一份剧本）
- 出片双路径：提示词文本为第一产物（可直接复制即梦手动出片），同时兼容 dreamina-canvas 自动出片喂参
- 独立项目 + 私有 GitHub 仓库；manju-pipeline 整个移除，经验全量迁入本套件

**非目标**
- IP 选择（用户自己选，小说或想法两种输入）
- 数据复盘/投放运营 skill（不在本套件）
- 即时预览机制（用户 2026-10-27 明确砍掉）

**反目标（做了即失败）**
- 「塑料 AI 感」提示词（4K/8K/杰作/超清晰类废话词）
- 硬切转场、转场无时空交代
- 品牌植入（画面/语音/字幕三层都禁）
- 未经批准烧积分；指令压缩/改写后出片

## 三、约束（继承自 manju-pipeline 的已验收硬闸，按 skill 归属）

- **Notion 唯一控制面**：数据记录/同步/审核在 Notion，生成状态=生成中才准出图出片（归属：出片检查）。**Schema 定案：沿用已验证字段契约（剧本表/人物表/资产节点/生成状态），每部剧一个新栏目，新增服装套/检查报告字段；不做旧数据迁移**
- **出片执行定案（2026-10-27 用户定）：自动为主**——skill 经共享花钱门（报价→用户批→跑）直调 dreamina-canvas 出图出片；验真走 submission.resources 自动回填 Notion；手动贴即梦仅作备选路径。**花钱门是 shared/ 里唯一共享闸模块，凡扣积分必过（含素材图）**；shot-qa 只做检查与报价不亲自执行
- **花钱门**：任何扣积分调用先报价发账单，用户批了才跑；`node quote` 报价可能低于 `--run` 实估，超账单必须重新获批（归属：出片检查）
- **广告植入闸**：禁真实品牌名、品牌感商品包装（指令写死素色无品牌+禁包装特写）、品牌 Logo；**语音、字幕层同样禁品牌**（归属：分镜创作自检+出片检查扫描）
- **转场交代规则**：场景/时间变化的进场镜必须含地点+时间（旁白「时间，地点，场景变化逻辑」或屏幕 UI 层字幕卡）+ 转场过渡句（空间延续、明写不硬切）（归属：分镜创作强制项）
- **零压缩铁律**：Notion 指令=原始数据，出片逐字搬运，SHA-256 校验（归属：出片检查）
- **结果验真**：只认提交时刻后的新 resource，看 `submission.resources` 不看 node 旧快照（归属：出片检查）
- **一枪一停/原节点重跑/重制不夹带**（归属：出片检查）
- **即梦/Seedance 规格**：单次≤15s 自动分段、中文提示词≤500 字、每时间片一个动作一个运镜、写实真人面部转 3D/cel-shaded 防拦截、情绪必须可视化（归属：分镜创作）

## 四、五个 skill 设计

### 1. `novel-to-drama` 小说改编

**输入**：小说（链接或文本）。**输出**：分集方案 + 分集剧本。

流程：
1. **抽正文**：迁移 manju-pipeline 现有工具链（番茄字体反爬→本地渲染+macOS Vision OCR，浏览器页内导出 raw→重建，差集校验）
2. **拆解**：逐卷精读——人物盘点（主角/配角/路人三级）、人物弧线与关系演进、伏笔、名场面、爽点/冲突密度分布
3. **分集方案**：**单集时长自动决定，30–120 秒区间（2026-10-27 用户定）——由拆分出的剧情节拍与分镜自然成型，不硬凑、不牵强**（不为凑时长注水、不为压时长砍戏）。分集单元是剧情节拍/名场面，不是章节——禁止「一章=一集」机械映射：一集可跨多章取材，一章名场面密度高也可拆成多集；每集必须装满戏剧容量（冲突/钩子），一章文字直接压一集「表达不够」即为分集失败。连贯标题必须同集；名场面独立成集加爆点
4. **拆分与改编方法论（2026-10-27 用户供，落 `shared/split-methodology.md`，小说/想法两 skill 共用）**：
   - **换算锚（参考非定值，剧情刀口优先）**：微短剧剧本 1 分钟 ≈ 200–400 字（对话密集、动作精简）；一章 2000–4000 字参考拆 3–5 集（1–2 分钟/集）或 2–3 集（3–5 分钟/集）——最终仍由故事单元与时长区间（30–120s）自然决定，字数只做初算锚，禁止按字数硬切
   - **按故事单元拆，不按字数**：一集一个微事件＝明确目标/冲突＋起承转合（哪怕很短）＋结尾钩子（Cliffhanger）；单集 1–3 个场景，一章 5 场景按转折点/情绪高潮分组；拆分刀口跟情节点走（发现线索→遭遇阻碍→突破/反转，标出转折点再分组场景）
   - **连贯改编技法**：叙述→视听——心理/背景描写转动作、表情、潜台词、环境细节（「他很害怕」→「手心出汗、后退一步、声音颤抖」，与分镜创作的情绪可视化同源）；每集结尾必留钩子，原文平缓就调顺序、把后面的冲突提前；人物说话方式/性格靠对话和选择体现，不用旁白交代；**开头 5 秒抓人**——慢热开头重构成动作/对话直入；多集主线贯穿（同一核心目标，可用倒计时/任务清单串联），每集开头自然承接上集
   - **每集结构模板**：第 1 集建置目标+第一冲突+悬念 → 中间集冲突升级/受挫+更危急钩子 → 末集高潮解决+收尾或引下一章；每集撰写后过连贯性检查（开头承接+结尾钩子）再定稿
5. **分集剧本**：按剧本两核心产出——灵活叙事（冲突密度、砍水戏、每场戏直接可拆镜头、产出即进分镜不返工）、剧本理解（原著人物/伏笔/名场面不走样，保留原作梗与名台词≤20字）

### 2. `idea-to-drama` 想法创作

**输入**：用户的想法（一句话到一段）。**输出**：原创分集剧本 + 集数规划。

流程：需求澄清（题材/受众/单集时长/集数盘子，最多追问 2 问）→ **搜索**同类题材与爆款冲突结构（联网检索市场偏好）→ 戏剧结构（logline→多集结构→人物小传）→ 分集剧本（同两核心标准）。

### 3. `storyboard-director` 分镜创作

**定位**：虚拟导演 + 即梦（Seedance）视频提示词工程师，把剧本变成可直接复制到即梦出视频的专业提示词。**镜头要细，方便后期拼接制作**（用户强调）。

- **六要素提示词**：主体外貌 + 动作 + 场景 + 光影 + 焦段运镜 + 音效；每时间片只放一个动作、一个运镜（防画面抖）
- **资源库**：50+ 安全运镜词典（好莱坞运镜术语）、导演风格库（维伦纽瓦/韦斯·安德森/新海诚/武侠等）、三层光影体系
- **7 项强制自检**（全过才交付）：长度、时间轴、运镜专业度、废话词拦截、素材引用数、冲突检测、裸英文运镜词
- **转场强制项**（留存主轴 1）：转场镜必交代时间+地点（旁白或字幕卡）+转场过渡句；同场景多镜保持空间/光影连贯
- **硬规则**：>15s 自动拆段、中文≤500 字、禁废话词（用物理材质词替代）、情绪可视化（「泪水滑落、嘴唇微颤」而非「她很伤心」）、参考图默认多参考图语义（明确说「当首帧」才走首帧路径）、写实转 3D/cel-shaded
- **交付格式**：主题 → 素材映射（哪镜挂哪张人物/场景资产）→ 导演阐述（为什么这么拍）→ 代码块完整提示词（直接复制即梦）

### 4. `asset-studio` 人物与场景素材

**输入**：剧本。**输出**：与分镜逐镜关联的人物图、场景图。

- **资产体系（三视图锚点制）**：角色主体三视图=身份锚（脸/身材/头身比，永久）+ 每套服装三视图=可替换模块（剧情换装出多套，逐件写死版型+配饰拆解）+ 表情表 + 面部身份卡/色卡；场景图=纯空镜（无人）
- **出图前置调研（固定工序，用户 2026-10-27 强调）**：每次出图前先检索资料——这个风格该怎么出图、提示词怎么写才精准、别人的翻车点——对齐核心要素（主体+三视图+表情+多套服装+风格质感+跨镜一致性）再出指令
- **风格库**：3D 卡通渲染/日漫/国漫/皮克斯等各风格的出图经验、提示词模板、负面词表、常见翻车点；调研结论沉淀回库，越用越准
- **一致性硬规则**：服装三视图 i2i 挂主体三视图（同光影/站姿/机位）；同场景多镜共用同一套场景资产；每镜按分镜的素材映射挂参

### 5. `shot-qa` 出片检查

**输入**：分镜+素材+出片计划。**输出**：检查报告 / exec plan，全过才准出片。

三道闸：
1. **价格闸（花钱门）**：逐镜报价（单价×数量），账单发用户批准；超估重新批
2. **分镜剧情校验**：分镜↔剧本逐字一致（SHA-256 级）、转场交代齐（时间+地点+过渡）、广告植入扫描（品牌词表+商品包装词，台词/旁白/弹幕一并扫）、违禁词、每镜≥250 字、看点/钩子句号收尾
3. **素材校验**：每镜该挂的人物/场景资产挂齐（露脸角色全挂、场景必挂）、ref ID 格式（node_+10 位）、节点存在且 success、生成后验真（submission.resources、createdAt 晚于提交）
